# 雅思写作 AI 试用工具（独立版）

独立网页：手动输入题干、作文和（Task 1）题图，查看 **原稿评价 / 逐句精修 / 整篇改写**，可复制结果，并保留自己的历史记录。

## 隔离边界

| 项目 | 试用工具 | 主应用（不触碰） |
|---|---|---|
| 代码 | `tools/ielts_writing_ai/`，不 import `app` / `models` / `config` / `api` / `services` | `app.py` 等 |
| 进程 / 端口 | 自己的进程，默认 `127.0.0.1:5055`；拒绝 5000 / 5002 | gunicorn `:5002` |
| 数据库 | 自己的 SQLite：`<数据目录>/iwa.sqlite3`；拒绝 `app.db` 文件名和含其他表的库 | 生产库 |
| 配置 | 只读 `IWA_*` 变量和 `tools/ielts_writing_ai/.env` | `DEEPSEEK_API_KEY` 等不读 |
| 上传 | `<数据目录>/uploads/<用户>/` | — |
| 登录 | 管理员发放的试用码，Cookie 名 `iwa_session` | 学习系统账号 |
| 部署 | **不在** `deploy.yml` / `deploy-studytracker` 里；push 到 main 不会启动它 | 自动部署 |

不改导航、小程序、正式成绩、MockExamReview，也不做生产表迁移。

## 本地快速开始

在仓库根目录执行：

```bash
# 1. 独立虚拟环境（只需 Flask；gunicorn 仅测试环境用）
python3 -m venv tools/ielts_writing_ai/.venv
tools/ielts_writing_ai/.venv/bin/pip install -r tools/ielts_writing_ai/requirements.txt

# 2. 配置（默认 fake 演示模式，不调用任何付费 API）
cp tools/ielts_writing_ai/.env.example tools/ielts_writing_ai/.env

# 3. 创建试用用户（试用码只显示一次）
tools/ielts_writing_ai/.venv/bin/python -m tools.ielts_writing_ai user-add --name 张三 --days 14

# 4. 启动 / 查看状态 / 停止
tools/ielts_writing_ai/bin/start.sh     # → http://127.0.0.1:5055/
tools/ielts_writing_ai/bin/status.sh
tools/ielts_writing_ai/bin/stop.sh      # 只停核验通过的试用工具进程
```

**进程安全**

- **PID 文件**：记录 PID、进程启动时间（`ps lstart`）和启动方式。`stop.sh`、`status.sh`、`start.sh` 只有在“进程存活、启动时间一致、命令行属于本工具”三项都满足时，才认定这是本工具的实例。PID 被其他程序复用时，脚本不会发任何信号，只清理过期的 PID 文件。
- **旧版 PID 文件**：只有一个数字、没有启动时间，无法核验，脚本不会自动停止，并会给出手动确认的命令。
- **单实例锁**：同一个数据库只允许一个实例运行，锁文件是 `<数据库>.lock`，用操作系统的 `flock` 实现，进程退出后自动释放。第二个实例会在动任务状态之前直接退出，不会把正在运行的实例的任务标成“中断”。`IWA_LOCK_WAIT`（默认 5 秒）控制等待上一个进程退出的时间。
- **启动成功判定**：`start.sh` 只认刚启动的那个进程返回的健康检查。端口被别的服务器占用时会报启动失败，不会误报成功。
- **并发启停**：`start.sh` 和 `stop.sh` 先由 `ctl_lock.py` 取得 `<数据目录>/iwa.ctl.flock` 上的 `fcntl.flock` 排他锁，再用 `exec` 把自己替换成启停脚本（PID 不变），锁放在 9 号文件描述符上。
  - 执行启停逻辑的进程本身就是持锁者，没有单独的包装器进程，所以杀掉任何一个进程都不会在操作还在进行时释放锁。
  - 操作中启动的短命子进程（curl、sleep 等）同样持有这把锁；最后一个持有者退出时（包括被 SIGKILL），内核才会释放。
  - 后台服务用 `9>&-` 关掉 9 号描述符启动，并清除锁相关的环境变量，所以服务进程不持有锁。
  - 只是从父进程继承来的锁环境变量不能绕过加锁，因为会核对持锁 PID。
  - `ctl_lock.py` 只依赖 Python 标准库；等待时间由 `IWA_CTL_LOCK_TIMEOUT` 控制（默认 60 秒），超时退出码 75，不做任何改动。
  - 多个 start 同时运行时只会启动一个实例；启动失败时，只有 PID 文件记录的是自己的 PID 才会删除它。
- **Shell 兼容**：脚本兼容 macOS 自带的 `/bin/bash` 3.2，所有变量都写成 `${VAR}`。原因是 bash 3.2 在 UTF-8 环境下会把紧跟在 `$VAR` 后面的中文字节读进变量名，导致报错；测试里有静态检查。

前台调试可以直接运行 `python -m tools.ielts_writing_ai serve`，按 Ctrl+C 退出。数据、日志、PID 和会话密钥都放在 `tools/ielts_writing_ai/var/`（已被 git 忽略）；用 `IWA_DATA_DIR` 可以改到别处。

## 接入真实模型

编辑 `.env`：

```bash
IWA_LLM_PROVIDER=deepseek          # 或 qwen / openai_compatible
IWA_LLM_API_KEY=sk-...             # 试用工具专用 Key，建议单独申请、单独限额
# IWA_LLM_MODEL=deepseek-flash     # qwen 默认 qwen-plus，可改 qwen-max 等

# Task 1 题图识别（可选）：先由识图模型提取图表数据，再交给文本模型评价
IWA_VISION_PROVIDER=qwen           # 默认 none：题图只保存展示，评价会提示“未核对图表数据”
# IWA_VISION_MODEL=qwen-vl-max-latest
# IWA_VISION_API_KEY=              # 不填沿用 IWA_LLM_API_KEY
```

运行 `python -m tools.ielts_writing_ai check` 可以查看生效配置（不会打印 Key）。修改配置后需要先 `stop.sh` 再 `start.sh`。

DeepSeek 默认使用 `deepseek-flash` 的非思考模式。

**原稿评价的思考模式（试验开关，默认关闭）**：

```bash
IWA_EVALUATE_THINKING=off                # off（默认）/ high / max；只影响原稿评价，精修和改写不变
IWA_EVALUATE_THINKING_MAX_TOKENS=16000   # 思考时的输出上限（暂定，需按实测校准）
IWA_EVALUATE_THINKING_TIMEOUT=300        # 思考时的单次超时秒数（暂定）
```

- 思考档位：`high` 和 `max` 都会作为 `reasoning_effort` 发送。服务商把 `xhigh` 映射为 high，所以不单独提供。`max` 的输出上限和超时同样用上面两项，需要实测后再定。
- **默认保持 off 是因为质量还没验收完，不代表 off 比 high 更准。**第一次同条件对照（提示词 `.6`，7 篇，2026-11-04）：high 对部分上下文判断有改善，但中位耗时约为 off 的 2.8 倍，输出 token 约为 3.9 倍，仍有误读和无来源建议，不足以切换默认值。high 适合作为老师复核时的试验选项。
- 设为 `high` 时，评价请求发送 `"thinking": {"type": "enabled"}` 和 `"reasoning_effort": "high"`；关闭时和以前一样发送 `{"type": "disabled"}`。目前只支持 DeepSeek，其他服务商开启会报配置错误。
- 思考内容（`reasoning_content`）不解析、不保存到结果里、也不给学生看；严格 JSON 校验只看正式回答。realcheck 会把它留在本机的 `raw_calls.jsonl` 里，方便复核。
- 用户已在本机核对官方文档：`thinking: {"type": "enabled"}` 和顶层的 `reasoning_effort: "high"` 写法正确；思考内容与正式回答分开返回；`usage` 里有 `completion_tokens_details.reasoning_tokens`；思考模式下 temperature 不起作用。文档写法正确不等于已经实际连通，仍要先跑 1 次连通性测试。
- 4500 token 的上限和 120 秒超时是在关闭思考时测出来的，开启后不沿用：思考时使用上面两项单独的设置。16000 / 300 是暂定值，需要用对照实测的输出峰值和延迟重新设定。
- 页面和复制文本的来源一行会标明“思考模式 high”。HTTPS 始终校验证书和域名；系统没有根证书时，使用独立依赖中的 certifi 证书包补充。遇到证书错误不要关闭验证。客户端拒绝 HTTP 重定向，避免凭据被转发及绕过请求计数。

成本控制：每人每天 `IWA_DAILY_LIMIT` 次生成（一次批改消耗 3 次，重新生成消耗 1 次，删除记录不返还）；同时进行的模型调用数不超过 `IWA_MAX_WORKERS`。

## 评分规则（防止无依据的分数）

- **每项都要有依据**：每个评分项都必须有评分理由，并且至少有一条能在学生原文中逐字找到的引文（优点和问题都带引文）。缺少理由或证据、缺少总评或提升重点的输出会被拒绝：系统自动重试一次（不额外扣额度），仍不合格就标记为失败，不显示任何分数。
- **引文核对**：找不到的引文会在页面和复制文本里标注“未在原文中找到，不作为评分依据”。
- **Task 1**：只有题图被识图模型读出了足够的数据时，才评 Task Achievement 和总分。
  - 识图模型必须返回结构化结果：可读性（sufficient / partial / unreadable）、图表类型、数据点、主要特征、读不清的部分。
  - 是否“足够”由服务端判定：
    - 柱状图、折线图、饼图、表格、组合图：至少 3 个带数值的数据点，并且有主要特征；读不清的部分不能多于读清的部分。
    - 地图：至少 2 处变化。
    - 流程图：至少 3 个步骤。
    - 描述里出现空白、看不清等字样，一律判为不足。
  - 识图接口调用成功不代表题图可用：返回纯文本、可读性为 partial 或 unreadable、数据不足，都会显示“题图信息不足（原因）”。
  - 未上传题图、未配置识图模型、识图失败、信息不足这几种情况下，TA 和总分都显示“不可评”，只保留 CC / LR / GRA；改写稿也会提示数据没有与题图核对。
- **改写质量检查**：模型对改写稿的自述一律不直接采信（依据是 2026-11-04 的两批真实验证和两轮离线复核）。
  - **字数**：显示的字数都是服务端计数。改写稿低于 150 / 250 词下限，属于正文问题。说明里的每个字数按所在分句判断：指原稿、指目标 / 下限，还是指当前改写稿。只有目标 / 下限不核对。
  - **改动说明是结构化数据**：每条为 `{before: 原稿原文, after: 改写稿原文, why: 说明}`，也接受模型用过的 `old/new` 写法。核实条件有三个：`before` 在原稿中，`after` 在改写稿中，并且这段文字在两稿中的出现次数说明修改确实发生了（`after` 出现得更多，或 `before` 出现得更少）。所以 `cut air pollution` 不会被当成删除；去掉一个 `the` 也不会因为文中别处还有 `the` 而被误判；正文没变却声称修改的会被删除。自由文字形式的说明无法核实，不予采用。如果原稿已经达到目标、无需修改，模型应返回原文、`key_changes []`，并在 `unchanged_reason` 里说明原因，这种情况不算问题。
  - **自称达分**：说明里声称“达到 / 符合 Band X”“已达到雅思写作 7 分”“是一篇 7 分作文”等，只算 AI 自述，会被标出。否定（“未达到”）、目标（“为了达到 7 分”“向 Band 7 靠近”）以及谈原稿的说法不算。
  - **是否回应题目**：关键词重合度不能判断是否切题，只在很低时给一条不确定提示（计算时去掉考试说明）。“题目要求 → 对应原句”对照至少要有 2 条，并且引文必须在改写稿里，但它只能证明这些句子存在。唯一的确定性判断是：模型自己说原文离题，而改写稿仍有 ≥ 50% 的内容词来自原文、与题干重合不到 30%，这时判为“仍沿用离题原文”。模型的离题标记只显示为“需要人工确认”，不会被说成“已按题目重答”。评价给原文的 TR / TA ≤ 4.5 时，改写页也会提示需要人工确认是否切题。
  - **Task 1 缺图**：声称“数据准确”的算问题；“无法确认数据准确”这类诚实说明不算。
  - **处理方式**：问题分为两类。正文问题指字数不足、仍沿用离题原文；说明问题指改动说明、字数自述、自称达分、题目对照这些。
    - 只有说明问题时，不重写正文，只发一次“修说明”的请求，让模型针对这篇改写稿重新给出说明。修好了就通过；没修好或请求失败，就保留原正文和已经核实的说明。这样修好的正文不会因为说明写错而被换掉。
    - 有正文问题时，整篇重新生成一次，然后按“正文问题数 → 说明问题数 → 轮次”选稿，打平时保留先出的一稿。
    - 这两种情况都最多只发 1 次额外请求，不额外扣额度。重试调用失败时保留首稿并说明原因。
- **Task 2 论证结构检查**（不单独计分，用来解释 TR / CC 的分数）。判断准则依据第三批真实验证（2026-11-04，8 次评价）的人工审阅修订，提示词 `iwa-2026-11-04.5`：
  - **只报告真实的论证缺陷，把“可以更好”单列**：
    - 限定立场就是一个立场。例如“部分同意”“优先公交，必要时修路”，承认例外不算立场不清，也不算前后矛盾。
    - 支撑可以有多种形式：因果解释、比较、后果、个人或假设的例子。**不要求具名城市、研究或统计数字。** 有理由但写得简短，属于可选优化，不是“没有支撑”。
    - **先看整段再下结论**（提示词 `.6`）：判“论点没有任何理由支撑”或“例子没有回扣论点”之前，模型必须在 `support_found` 里列出同一段已有的理由、机制、例子，或例子所说明的论点。从句（because / so / where / which / if…then）和相邻句子都算；例子紧跟在论点后面就算已经回扣，不必再加一句“这说明……”。只要模型列出的支撑能在原文同一段找到、并且不只是问题引文本身，服务端就把这条改列为可选优化（显示“原判……，同段已有……”），不再算论证问题。注意：这只能证明同一段确实有这句话，不能证明它构成有效支撑；是否合理仍需要模型判断和人工校准。
    - 让步如果是在界定立场的范围（立场本身就允许的例外），不需要反驳。只有对方论点削弱了立场、而文章没有回到立场时，才算“让步后没有回到立场”。
    - 让论证更强的建议（更多细节、更清楚的主题句、再加一个例子）放进 `improvements`，页面显示为“可选优化（不是错误）”，不计入问题数，也不压低分数。可选优化本身就是建议，所以模型把建议写在 `comment` 而没有 `suggestion` 时（2026-11-06 一篇作文的 3 条全是这样），用 `comment` 的文字作为建议；引文核实和数字来源检查照样适用，两个都有时以 `suggestion` 为准。
    - 假设的例子只能用文字描述，不能带原文没有的数字（提示词 `.9`）：写“一辆坐满的公交车能代替很多辆私家车”，不写“一辆载 40 人的公交车”。后者仍会被数字检查删掉，但提示里以前写“可以用假设的例子”，等于鼓励了这种写法。
  - **矛盾必须成对举证**：“立场前后矛盾”“结尾与立场矛盾”必须同时引用两处原文（`quote` 和 `conflicts_with`）。两处都要能在原文中找到，并且不是同一段文字，否则丢弃。“立场不清”（通读全文仍看不出作者的观点）和“立场前后矛盾”分为两类。
  - **AI 的判断必须自洽**，服务端会检查三种情况：
    - 判为“立场一致”，却又报告了矛盾：立场一致性不下结论，相关问题标“需人工确认”；
    - 判为“立场不一致”，却没有可核实的矛盾对：这个判断不采用；
    - 判为“服务于立场”的段落，又被报告为偏离：标“需人工确认”。
    这些都会在这一节顶部提示，不会被悄悄保留。
  - **不推荐没有来源的数据**：见下面的“建议里的数字”。
  - **绑定真实段落**：评价提示给每段编号，每条段落分析必须对应一个真实段落。服务端按引文所在位置定段，模型给的段号只用来在多个候选段之间选择。同一段的第二条记为重复。原文只有 1 段时，会提示只能按整段分析。
  - 问题类型共 11 类，见 `argument.PROBLEM_TYPES`。立场、每段、每条问题、每条可选优化各算 1 条，每条只会落入下面一类：
    - 采用；
    - 丢弃：不是对象、字段类型不对、类型 / 角色 / 判定不在列表里、缺少文字、引文找不到、矛盾缺少另一处引文，或者可选优化只剩被删去的数字；
    - 重复：同一段的第二条，或者同类型、同引文的问题；
    - 超出上限：可核实，但超过 8 段 / 6 条问题 / 3 条可选优化。
    因此“模型给出 = 采用 + 丢弃 + 重复 + 超出上限”。
  - 每条引文都要先完整核对、再截短显示（评分项的引文也一样）。无效条目只影响它自己。只有 Task 2 评价缺少 `argument`，或者没有一条可核实的段落中心句时，才整份按不合格处理，静默重试一次。
  - **一个完整的顶层 schema**（提示词 `.9` 起评分项也在最外层）：提示里给出整份回答的模板，`task`、`coherence`、`lexical`、`grammar` 四个评分项和 `argument`（Task 2）或 `comparisons`（Task 1）、`overall_comment`、`priorities` 都在最外层，按这个顺序各出现一次。以前多包一层 `criteria`，真实运行里三次（2026-11-04 weak、2026-11-06 短文两次）都是 `criteria` 写完后少了一个 `}`，后面的内容全被套了进去；去掉这一层就不会再出现这种错位。旧的 `criteria` 写法仍然接受，但两种写法同时出现会被拒绝；如果这些字段被放进了评分项里，重试提示会写明“放错了位置”。仍然保持严格解析，不会自动补全 JSON。
  - **格式错误会说清楚错在哪**（`jsonshape.py`）：回复不是一个合法 JSON 对象时，重试提示会写明具体问题，例如“argument、overall_comment、priorities 被写进了 criteria 里面：criteria 写完后少了一个 }”或“最外层对象在 overall_comment 之后就结束了，后面的 priorities 落在了 JSON 之外”。以前一律说“JSON 之外不能有其他文字”，结果短文的第二次重试犯了同样的错。这只是诊断：回复不会被修补或采用，重试的回答必须自己完整合法。realcheck 报告在合格率表下面逐次列出这些诊断，首轮被拒原因分成“JSON 之外有文字或不是 JSON 对象”和“JSON 括号或结构错误”两类。
  - 模型输出是不可信数据：解析时遇到意外的数据结构，按“模型输出结构异常”处理（评价 / 精修会重试一次，修说明会保留第一版正文），不会变成内部错误。
  - 页面在“下一步提升重点”下方单列“论证结构检查”：段号、角色和判定、矛盾的另一处原文（可点击定位）、“需人工确认”标记、可选优化。复制评价时会带上同样的内容。
  - 整篇改写的 Task 2 要求同步修正论证链，并在改动说明的 `why` 里写出修的是哪类问题。
- **建议里的数字必须有来源**（`figures.py`，适用于整份评价里所有给学生的建议：评分项问题的建议、论证问题的建议、可选优化、提升重点）：
  - 最后还有一遍总检查：结果里所有会显示给学生的建议（包括从“没有支撑”改列成可选优化的那些）都要再过一遍同样的规则。改列时，如果原建议已被删去，不会再用模型的说明文字补上；只有原本没有建议时，才用说明文字代替，而且说明文字也要先通过检查。
  - 建议里出现的百分比，以及 10 以上的数字（统计、年份、道路编号等），必须能在学生原文、题目、可用的题图识别结果里找到，或者等于本篇字数、字数下限。**篇幅目标不算数据**：紧跟“词 / 字 / 单词 / words”的数字（包括“260-300 词”这样的范围），或“字数达到 260”这样的说法，是写作目标，600 以内都保留，例如“扩写到 260 词以上”；“减少 260 次事故”不是篇幅目标，仍要有来源。否则删去这条建议：评分项和论证问题本身保留，并显示“建议含原文和题目都没有的具体数字，已删去”；提升重点删掉这一条；可选优化整条丢弃。评价顶部会汇总删了几条、分别在哪里。
  - 数字按完整数值比较：原文里的 1980、180 不能当作 80% 的来源。百分比必须对应原文里同样的百分比；普通数字只要数值相同（`1,500` 与 `1500` 视为相同）。中文百分比按数值比较：“百分之八十”等于 80%，“百分之八十一”不能当作“百分之八十”的来源，“百分之8”也算百分比。“补 1 个例子”“第 2 段”这类 10 以下的结构性数字不受影响。
  - 英文数词也会读出来：“forty”“forty-two”“one hundred and twenty”“a hundred”都按数值比较；“1.5 million”算作 1500000，不按小于 10 放过；“twenty-first” 这样的序数词不算。倍数（“forty times as many”“three times”“40-fold”）是事实说法，来源里必须有同样的倍数，小数字也一样，原文只有普通的 40 不能作为“forty times”的来源。时间跨度（“twenty years later”“two decades”）如果等于来源中两个年份的差（例如 2000 和 2020 相差 20 年），就算有来源。“twice”“a third”这类写法目前不识别。
  - 数词按英语数字的写法读，而不是逐词相加：一个数里，hundred 之后的 “and” 只能接 100 以内的尾数（“one hundred and twenty-five” 是 125，“two thousand and twenty” 是 2020），thousand、million 等单位从大到小排列（“one million two hundred and thirty-four thousand” 是 1234000）。所以并列的数词是几个数：“forty and fifty” 是 40 和 50，“one hundred and two hundred” 是 100 和 200，“one thousand and two thousand” 是 1000 和 2000，都不会合成 90、10200 或 3000。
  - 年份必须有上下文证明：前面有 in / from / to / by / between 等，后面接“年”，或是 2000-2020 这样的年份区间，才用来推算时间跨度。数字后面紧跟复数名词或量词时是数量，不是年份，即使前面有 from / between：“rose from 2000 to 2020 buses”“between 2000 and 2020 buses”“2000 辆和 2020 辆”都不算年份。区间一端是数量，另一端也按数量处理。本篇字数、字数下限可以作为篇幅和普通数字的来源，但不能作为时间跨度的来源：一篇 20 词的作文不能支撑 “twenty years later”。已知的保守处：年份后面直接接复数名词且没有逗号（“In 2000 sales rose”）会被当成数量，结果是由这对年份推出的时间跨度建议被删去，不会放过编造的数字。
  - 这里检查的是数字有没有来源，不核实说法本身对不对。评分理由、说明、总评这类解释文字，以及精修、改写的正文，不在这项检查范围内。
- **不预设分数、不强迫挑错**（提示词 `.8`）：每个评分项的问题可以是 0–4 条，没有明确的错误或不足时就留空，不得为了凑数编造问题；评分依据只在问题和优点里，所以没有问题时由优点提供原文证据（两者都没有核实过的引文，仍然拒绝）。提示里不再写“多数考生在 5.0–6.5”这类预设范围，只要求按评分标准、依据本文证据评分，不往高也不往低偏。
- **语言建议不能改变原意**（提示词 `.7`，依据思考模式对照时的人工审阅）：
  - 判定某个结构有错之前，要读完整句：正确的 which 从句、“much less crowded”这样自然的说法都不算错误；准确、自然优先于换更少见的词。
  - 改句和示范句必须保留作者的意思，不能加入作者没写的事实、原因、数字、倍数或趋势。例如不能把 “do not have cars” 改成 “cannot afford a car”，也不能把只有两个年份的数据写成 “a steady climb”。
  - 给出完整可用的句子，不给残句。描述某段或概述写了什么之前，先确认它真的写了。
  - Task 2 先审题（题型）：讨论双方并给出观点、同意的程度、利是否大于弊、两个问题等，题目要求的每一部分都要按要求回答；漏掉的部分（例如没有自己的观点、没有回答利是否大于弊）属于 TR 问题。
- **计数说法要和原文一致**：评价提示里给出段落数（`paragraph_count`）。评价中如果说原文是“N 段式”“共 N 段”“分为 N 段”，或者说某个英文单词“多次出现 / 反复出现 / 重复使用”，服务端会和原文核对（单词计入 s / es 复数形式）。不符的会在评价顶部附一条更正，例如“评价中说原文是‘四段式’，按换行计原文实际有 5 段”；原文本身不改。第四批真实验证中，Task 1 就有这两类错误。
- **语言建议要能直接替换，定性要准**（提示词 `.9`）：建议放回引文的位置后，整句必须是正确的句子；如果整句仍然有错（例如单独成句的 Because 从句），就引用整句、改整句。只有真的语法错误才叫语法错误：and / but 连接的两个分句可以有不同主语；-ing 短语的主语从句子里能看清，就不是垂悬分词。更精确的说法（百分比用 “the figure for Country B” 而不是 “Country B”）属于“表达更精确”，在问题说明和提升重点里都不能说成语法错误。
- **总评和提升重点要和细项一致**（提示词 `.9`）：评分项或论证分析里已经认可的内容（例如“已有因果机制”），总评和提升重点不能再说它缺失或只有断言；想建议更进一步时，要先说明原文已经有什么。
- **解释必须是简体中文**：每个评分理由和总评都必须含中文（里面引用英文原文没有问题），多数优点 / 问题说明也必须是中文，否则按不合格输出重试一次。第三批真实验证中，Task 1 的评价全部是英文。
- **Task 1 文内自洽**：模型要在 `comparisons` 里列出作文中**每一个**排序或比较说法（最高、超过、两年都、翻倍……），逐条与作文自己给出的数字核对。判为不成立的，必须带上能在原文找到的对照数字，才显示为矛盾（页面显示“对照：……”）。“对照”保留模型列出的、能在原文找到的**全部**数字（去重，按模型的顺序），页面和复制文本都完整显示，程序不做挑选。挑选两次都截掉了决定矛盾的数字：2026-11-06 的真实输出把全文 8 个数字都列上了，旧逻辑取前 3 个，正好全是 2000 年的，而说明比较的是 2020 年的 80% 和 75%；改成“说明里提到的前 4 个”后，说明一旦提到 6 个数字，又只剩 2000 年的 4 个（2026-11-07 复核）。只有超过 30 个这个安全上限时才截断，并在页面和复制文本里写明“另有 N 个数字未列出”。提示词 `.9` 要求模型只列决定判断的数字（最多 4 个），但服务端不依赖这条要求。旧的 `consistency_issues` 写法仍然接受。这仍是 AI 标注，不是程序化的数值校验；第二、三批真实验证都漏掉了内置样本中 A / C 的矛盾，`comparisons` 是否有效要看下一批。
- **输出必须是纯 JSON**：评价、精修、改写和识图的回复必须整段是一个 JSON 对象，或整段只有一个 JSON 代码围栏。JSON 前后出现任何文字（例如“无法读图，下面只是示例”），整份回复都会被拒绝：文本生成会静默重试一次，仍不合格就判失败；识图则判为“题图信息不足”。
- **复制文本**：由服务端生成，都带“AI 生成，仅供学习参考，不是正式成绩”和全部限制提示。唯一例外是单句“复制”按钮，只复制那一句改句。

## 真实模型小样本验证（realcheck）

`realcheck` 和网页走的是同一条生成流程：相同的提示词、严格 JSON、证据规则，以及一次静默重试。它的特点：

- **不碰试用数据**：用临时数据库运行，不打开试用库，不占试用账号的额度；试用服务器可以同时开着。
- **安全**：不打印 Key。调用次数上限（`--max-calls`，默认 50，必须为正整数）覆盖实际 HTTP 请求：realcheck 禁止底层网络重试，只保留输出校验的一次重试。第一次调用遇到 Key 错误或网络错误时立即停止。
- **防止误调用**：调用付费模型必须加 `--confirm-paid`。

```bash
PY=tools/ielts_writing_ai/.venv/bin/python
# 0. 在 .env 里配置试用专用 Key（不要发到聊天或提交到 Git）
#    IWA_LLM_PROVIDER=deepseek
#    IWA_LLM_API_KEY=sk-...
$PY -m tools.ielts_writing_ai check                    # 确认 provider / model、llm_api_key_set=true

# 1. 连通性：1 篇、只做评价，最多 2 次调用
$PY -m tools.ielts_writing_ai realcheck --limit 1 --kinds evaluate --max-calls 2 --confirm-paid

# 2. 内置合成样本：7 篇 × 3 类，最多 42 次调用；填入当前单价（每百万 token）可以估算费用
$PY -m tools.ielts_writing_ai realcheck --confirm-paid --price-in <输入单价> --price-out <输出单价>

# 3. 校准：用老师评过分的作文（JSONL，每行一篇）
$PY -m tools.ielts_writing_ai realcheck --samples teacher.jsonl --confirm-paid
```

### 思考模式对照（同一提示词、同一批作文）

判断开启思考后评价是否更准，只能做同条件对照：除了评价的思考模式，提示词、模型、作文都不变。

```bash
# 0. 连通性：1 篇、只做评价、开启思考，最多 2 次调用。确认请求被接受（没有 HTTP 400）、
#    输出没有被截断，并看思考 token 是否单独报告
$PY -m tools.ielts_writing_ai realcheck --limit 1 --kinds evaluate --evaluate-thinking high --max-calls 2 --confirm-paid --out <目录0>

# 1. A：关闭思考；B：high。同样 7 篇、只做评价，每次最多 14 次调用
$PY -m tools.ielts_writing_ai realcheck --kinds evaluate --evaluate-thinking off  --max-calls 14 --confirm-paid --out <目录A> --price-in <输入单价> --price-out <输出单价>
$PY -m tools.ielts_writing_ai realcheck --kinds evaluate --evaluate-thinking high --max-calls 14 --confirm-paid --out <目录B> --price-in <输入单价> --price-out <输出单价>

# 2. 对照（不调用模型）。比较两个模型时加 --allow-model-change（提示词和实际输入仍须相同）
$PY -m tools.ielts_writing_ai realcheck-compare <目录A> <目录B> --price-in <输入单价> --price-out <输出单价>
```

- **建议的实验顺序**（每一步只改一个因素）：
  1. 同一模型、同一思考档位（high），只改提示词（`.8`：允许“没有明确问题”，去掉预设分数范围），看误批是否减少；
  2. 固定提示词，比较 high 与 max，以及另一款候选模型（`--allow-model-change`）；
  3. 用带老师批注 / 老师分数的独立作文评估误批、漏报和分数偏差，避免只在这 7 篇内置样本上反复调参。
- `realcheck-compare` 会先检查条件：服务商、模型、提示词版本、运行类型必须相同；每篇样本的题目、作文、目标分、题图状态和**题图识别结果**必须相同；并且**实际发送给评价模型的消息**（realcheck 为每次调用记录 sha256）必须一致。思考模式、输出上限和超时是请求选项，不在消息里，只有这几项可以不同。任何一项不符就拒绝对照。旧版报告没有消息指纹时会给出提示，只核对导出的输入。两次思考模式相同时只给提示，按重复性对照处理。
- `compare.md` 并排列出：首轮通过率、延迟、输入 / 输出 / 思考 token、单次输出峰值与上限、截断和超时、估算费用、论证问题数、改列可选优化数、自相矛盾数、计数更正数、删除的建议数，以及逐篇分数和论证问题；样本带老师分数时，还会给出与老师的对比。
- **哪一边更准，要看 `manual_review.md`**：它列出两次运行的以下内容，留空“判断 / 备注”列（正确 / 误判 / 过严 / 过松 / 不确定），每篇最后一行记录两次都漏掉的问题：
  - 立场判断，以及论证一节的提示；
  - 每条论证问题，带段号、“需人工确认”标记和成对矛盾的另一处原文；
  - 改列的可选优化，带同段支撑；
  - TR / CC 问题和计数更正；
  - Task 1 的文内矛盾（说法、对照数字、说明），以及核对了几条比较。
- 改列为可选优化的条目也要人工看：`support_found` 只能证明同一段确实有这句话，不能证明它构成有效支撑。开启思考也不能保证这一点。
- JSON 通过率只是其中一项；不能用自动检查全部通过来代替人工复核和老师评分校准。
- 思考 token 是否单独计费、是否已经包含在输出 token 里，以服务商账单为准。报告分别列出这两个数字，费用按输出 token 估算。
- 思考 token 按每次调用的 `usage.completion_tokens_details.reasoning_tokens` 统计，**失败的调用也算**（例如思考用完了上限）。只要有一次思考调用没有报告，报告就写“已知小计 N（另有 M 次没有报告，合计不完整）”，不会把小计当作合计。
- 输出达到上限（`finish_reason=length`）一律记为截断，即使正文为空（思考用完了上限）。截断不会作为不合格输出重试，这一篇评价直接失败，所以上限要按实测峰值留足余量。

内置样本（`samples.py`）是原创的合成作文，不含学生数据：

- 4 篇同题 Task 2，水平从弱到强。
- 1 篇离题作文、1 篇字数不足的作文。
- 1 篇没有题图的 Task 1。

报告会检查这些样本的分数是否落在宽松区间内，并检查总分是否随水平升高、最强和最弱至少相差 1.5 分。这些区间只用来做合理性检查，不是真实分数。

论证结构也有对应的合理性检查。“出现某类问题”会同时看三处：问题类型；段落判定（有段落判为偏离，等于出现 off_position）；立场一致性（有可核实矛盾对支持的“前后不一致”，等于出现 inconsistent_position）。问题条数只数问题列表，可选优化不算问题。

- 强文（t2-strong）：
  - 论证问题不超过 1 条；
  - 不出现 off_position / unclear_position / inconsistent_position / conclusion_inconsistent；
  - 能找到可核实的立场句。
- 弱文（t2-weak）：至少被指出 1 条问题。
- 离题作文（t2-off-topic）：要出现 off_position 或 irrelevant。
- 缺图 Task 1（t1-no-image）：要指出样本里已知的文内矛盾（A “两年都最高”，但 2020 年 C 超过了 A）。

没有运行的检查（例如只跑评价时的离题改写检查）显示为“–”，不计入通过数。

报告另列“论证结构”一节，包括：
- 立场找到率、段落判定分布、问题类型分布；
- 可选优化条数、AI 判断自相矛盾的处数、因含原文没有的数字而被删去的建议数；
- 条目统计“模型给出 = 采用 + 丢弃 + 重复 + 超出上限”以及丢弃率（丢弃 / 模型给出）。这里只统计最终采用的评价；
- 评价请求（含重试）中，有几次因为缺少论证结构或没有可核实的段落而被整份拒绝。这部分单独列出，不计入条目统计。

逐篇表也列出每篇的问题类型。

校准文件的每一行格式如下（`teacher` 里可以只填部分项；`image` 是相对于 JSONL 文件的路径，可选）：

```json
{"id": "s01", "task_type": "task2", "prompt": "题干……", "essay": "作文……", "teacher": {"overall": 6.5, "task": 6, "coherence": 6.5, "lexical": 6.5, "grammar": 6}}
```

样本还可以带老师批注：`"teacher_findings": [{"quote": "原文中的一段（逐字）", "note": "例子不贴题"}]`。加载时会检查每条 quote 是否真的在作文里。报告会新增“与老师批注对照”一节：
- **同一位置**指两段引文在原文中的字符区间相交。词语相似但在不同段落，不算同一位置。引文在原文中出现不止一次、只有部分位置相交时，记为“不确定”，不计为覆盖。
- **分母包括评价失败的作文**：它们的批注计为未覆盖，并单独标明；同时另给“只看评价成功的作文”的覆盖率，两个比例不会混在一起。
- `realcheck-compare` 的人工复核表按“引文 + 批注”逐条对齐 A / B，与批注在列表中的顺序无关。两次运行的批注不同时会给出提示，缺的一边标“无此批注”。
- 位置重合不代表判断相同；AI 指出、老师没批的地方也不一定是误判，需要人工看。

用真实学生作文校准时，作文会发送给模型服务商。请先征得同意，并去掉姓名等个人信息。

每行的 `id` 必须唯一；重复 ID 会在调用模型前被拒绝。

报告写在 `<数据目录>/realcheck/<时间>/`，这个目录被 git 忽略：

- `report.md`、`report.json`：首轮纯 JSON 率、首轮通过校验率、最终成功率、首轮被拒原因、引文核实率、论证结构统计、精修缺句率、改写达标率、延迟、token、合理性检查、与老师评分的误差。
- `raw_calls.jsonl`：每次调用的原文，方便排查。

报告区分接口是否响应、鉴权是否通过和内容是否通过校验；生成截断不等于网络不通。已返回的失败响应用量仍计入统计，未返回用量时标为未知，不能视为实际费用为零。文本与识图用量分别统计并汇总；提供的单价只覆盖对应文本模型，未提供独立视觉价格时不会把部分估算称为全部费用。

## 测试

```bash
tools/ielts_writing_ai/.venv/bin/python -m unittest discover -s tools/ielts_writing_ai/tests -t .
node --test tools/ielts_writing_ai/tests/test_draft.js
```

测试只用内存 / 临时目录、本地假服务器，以及测试自己创建的进程。不联网、不调用付费 API、不读取开发者的 `.env`，也不读写任何真实数据。

覆盖范围：

- **文本与评分**：断句、分数计算、模型输出与证据校验、Task 1 不可评、复制文本的限制提示。
- **模型调用**：真实 HTTP 客户端的行为、不合格输出的自动重试。
- **账号与隔离**：登录、CSRF、错误次数锁定、用户之间的隔离、草稿按用户隔离（node）。
- **数据与流程**：额度、上传校验、失败重试、原稿不被修改。
- **进程**：重启恢复、单实例锁，以及启停脚本不会误停其他进程（PID 复用、启动时间不符、旧格式 PID 文件、端口被占用）。
- **不依赖主应用**：用子进程检查不会 import 主应用。
- **真实模型验证工具**：用模型替身离线测试，覆盖首轮和最终合格率、Key 错误时立即停止、调用上限、试用库不被触碰、报告里不出现 Key、与老师评分的误差统计、付费调用必须确认。

`test_scripts.py` 需要 `curl` 和 `ps`（macOS 和 Linux 都自带），每次会真实启动、停止几个临时实例，大约需要 20 秒。

- 测试会用本机找到的所有 bash（macOS 上包括 `/bin/bash` 3.2），在 UTF-8 locale 下逐条检查启动、状态、停止的提示信息，并严格按 UTF-8 解码输出。
- 需要额外覆盖其他 shell 或 locale 时，可以设置 `IWA_TEST_BASH`、`IWA_TEST_LOCALE`、`IWA_TEST_LOCPATH`。例如在 Linux 上用 `localedef -i en_US -f ISO-8859-1` 生成 Latin-1 locale，它对 0x80–0xFF 字节的分类和 macOS 相同，可以复现 bash 3.2 的这个问题。

## 已知限制

- AI 给的分数是**预估**：四项平均后按 0.5 就近进位（和系统模考批改的口径一致），会有误差，可能偏高。页面和复制出的文本都标注了“仅供参考”。
- `fake` 演示模式只返回带【演示】标记的固定示例，页面顶部有黄色横幅提示。
- 论证结构检查是 AI 标注。服务端核实引文、类型、矛盾是否成对、判断是否自洽、建议里有没有无来源的数字，以及“没有支撑”是否与模型自己找到的同段支撑冲突，但不核实判断本身对不对。第四批真实验证（提示词 `.5`）中，强文已经没有论证问题，部分同意也不再被判为矛盾；但有理由或例子的地方仍偶尔被判为“没有支撑”。提示词 `.6` 加了 `support_found`，效果还要等下一批真实验证。自动检查全部通过也不代表评分准确：在用老师评过分的作文做校准之前，这一节只适合配合老师一起看。
- 新建页的草稿只保存在本机浏览器，并且按账号隔离。同一浏览器换人登录时，会清除其他账号留下的未提交草稿；主动退出时会先确认，再清除自己的草稿。页面不缓存，退出后按浏览器“后退”也看不到之前的内容。
- 每次修改提示词都要同步更新 `prompts.PROMPT_VERSION`，每条结果都会记录生成时用的模型和提示词版本。
