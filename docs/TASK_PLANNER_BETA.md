# 任务安排试用版

用户于2026-10-28授权制作并上线试用版，供助教试用两天。完整后续方案仍在旧资料树的 `docs/design/daily-auto-assignment-plan-20261028.md`；本文描述实际试用范围，不代表全部远期功能已实现。

## 试用入口与用法

- 网页后台“任务安排”：`/task-planner`。教师、助教、管理员登录后可用，权限范围与原任务管理一致。
- 选择学生、日期、任务类型与具体材料，保存草稿。草稿不进入学生列表。
- 检查内容后“确认安排”。修改内容或日期会回到草稿，需要重新确认。
- 选中学生后开启该学生的自动布置；初始所有学生均关闭。只为启用学生布置已确认的当日安排。
- 北京时间每日03:05开始执行，09:00前每15分钟补跑失败项；09:00之后不自动补发。关闭学生开关后，后续定时执行立即跳过该学生，已有正式任务保留。
- 当日已确认的安排可由助教明确点击“立即布置”；它会创建真实学生任务，操作前有确认提示。未来日期不能提前点击立即布置。
- “待处理”需要人工检查原因、修改或重新确认，不会每天复制旧作业。同日已有未发布、锁定或删除的课程计划发生冲突时，会显示执行失败，需要人工处理原计划。不发送微信提醒。

## 本版范围

支持明确选择题型专项的题组、阅读整篇、词汇范围及精听内容，保存内容选择并在发布前核验。固定按日期执行，不自动换题、挪动未来日程、重复布置或回填过去日期。题目或资源失效会停下并说明。

前置任务可选：不设置则按指定日期布置；设置后必须属于同一学生且已完成或有效提交，退回/部分通过不放行。词汇任务需该学生的真实结算记录。未完成仅阻塞关联安排，不阻塞整科。

本版先完成“人工选好、定时发布”的闭环。长期教材顺序规则、自动计算下一词段、批量补做、拖拽日历尚未提供；临时手动布置继续使用既有任务管理。助教需要重复布置相同内容时也使用既有带重复确认及原因的流程，本版不会自动绕过重复检查。

费用：调用的是本网站自己的后台接口，使用现有服务器与题库，不新增外部付费API、AI选题或微信消息调用。运行会使用少量现有服务器及数据库资源；学生后续练习原有服务的计费方式不因本功能改变。

已发布安排关联既有Task/PlanItem，在任务管理和学生列表中使用同一任务。未开始的误布置可沿原任务管理取消；计划引用不是学习活动，已开始任务的取消限制仍保留。原安排保留发布历史且不会重发。

## 数据与执行

- 新增三表：`task_planner_student`（学生启停）、`task_planner_entry`（预排/冻结内容/确认版本/正式任务关联）、`task_planner_event`（操作日志）。仅增表，不改现有表列或学习成绩。
- API注册沿用仓库的check-first新表创建方式；上线前备份生产SQLite。可用 `scripts/run_task_planner.py --init-schema` 独立创建这三张表。
- 调度脚本只加载Flask配置、模型与轻量服务，不导入`app.py`，不加载语音模型。
- `scripts/run_task_planner.py --dry-run`只返回当日可执行数量，不发布任务。输出不含姓名、令牌或题目答案。
- systemd文件位于`deploy/task-planner/`。定时运行使用既有生产库与代码，网页gunicorn仍保持5002、1 worker、gthread、6 threads。
- SQLite写锁保护版本复核、资源冲突检查、Task/PlanItem创建与计划状态同一事务；稳定布置键`planner:<entry>:<student>`不随编辑版本变化。失败回滚不留下半份任务。

## 发布、验收与停用

具体测试计数、Git提交、部署结果和timer状态以`docs/CODEX_HANDOFF.md`本轮条目为准。此说明文件本身不是发布成功证据。

发布步骤：合成测试与浏览器验收 → 生产SQLite一致性备份 → 提交/推送并沿现有部署链路发布 → 确认三表及HTTP鉴权 → 安装timer/service并核对北京时间 → 空库或关闭状态dry-run → 助教自行选学生启用。

试用结束或异常时，可在页面关闭相关学生；全局暂停命令为 `systemctl disable --now studytracker-task-planner.timer`。若服务正在执行，应等待或停止该oneshot服务，再核对已发布任务；关闭timer不能撤回已经提交的任务。回滚代码前先停timer，新表保留，禁止通过删表回滚或删除既有成绩。

验收不向真实学生发送测试任务、不代答、不修改真实结算；业务发布和启用后由助教的明确选题/确认行为决定正式任务。小程序无需因本版新增网页入口而重新上传，学生仍消费既有任务接口。
