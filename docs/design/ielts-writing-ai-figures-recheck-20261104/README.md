## 仍需处理的实际问题

### 1. 数字过滤误删合理的篇幅目标

97词样本原始回复有两条建议：

- TR建议：“将每个论点扩展为完整段落，补充原因、后果或假设性例子，使总字数达到260词以上。”
- 提升重点：“将全文扩展到260词以上，拆分为引言、两个主体段和结论四段。”

两条都被删掉，因为来源集合只有原稿97和任务下限250，没有260。这些是在设定修改目标，不是在编造统计事实；删除整条还顺带丢掉了展开理由、分段等有效建议。建议把明确的字数目标按上下文识别，保留合理目标；不要放开一般数字建议。离线回归应同时包含“扩写到260词可保留”“公交减少260次事故仍拒绝”和原1980/180不可作为80%来源的对照。

自动report的论证章节显示“建议被删0条”仅指argument，**不代表整份评价为0**。本报告和独立审计从每篇result.suggestions_removed汇总全部路径，实际为2条。

### 2. 已有支撑或明显关联仍偶尔被升级为错误

- 弱文在建议公交更便宜、更快之前，已经写了公交改善→更多人乘坐→拥堵减少，以及迟到、拥挤和票价高的问题。模型仍把最后的建议句判为“论点没有任何理由支撑”，忽略段落上下文；可以建议展开，但“没有理由”过强。
- 中等作文前句已写可靠公交能减少拥堵，紧接着用新地铁开通后道路不再拥堵举例。模型承认例子有效，却因没再写一句“这证明投资公交优于修路”而列为example_not_linked。更适合列可选优化，而非强制再加总结句。
