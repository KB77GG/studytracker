## 结论：一处新增的 P2 指令冲突应先修正

`prompts.py:260–263` 新规则把 “task relevance and argument quality” 一起归入 TR，并明确说它们永远不能作为 CC、LR、GRA 分数的理由。禁止用离题解释语法分是本轮需要的修正，但将全部 `argument quality` 排除在 CC 之外过宽。

同一个 Task 2 system message 还同时包含两条相反要求：

- `ARGUMENT_CHECKLIST` 开头（38–41 行附近）：论证诊断解释 Task Response **和** Coherence & Cohesion。
- 81–82 行：真实论证问题应反映在 task **和 coherence** 的评分理由中。

`COMMON_DESCRIPTORS` 也保留 CC 的逻辑推进、分段和指代要求。当前一处要求论证问题不能解释 CC，另一处要求在 CC 理由中反映论证问题。六篇 Task 2 的实际生成提示都包含这组矛盾；基线 `.10` 没有新增的那条全面排除句。可以确认的是提示内部冲突，不能由此声称 `.11` 已经误扣或漏扣某篇真实分数。

建议按证据属性拆分，而不是只删掉一个维度名：

1. 是否回应题目、立场是否明确、观点是否充分展开和得到支撑，用于 TR。
2. 观点和段落如何排序、文章推进能否跟随、句段间连接及指代是否清楚，用于 CC。
3. LR 和 GRA 分别根据词汇与语法自身证据判断，不因离题或论证观点的好坏直接升降。
4. 论证检查仍可帮助解释 TR 或 CC，但必须说明具体属于哪项特征，避免“所有问题同时反映到两项”的笼统指令。

这是可以先离线修复的确定问题，不需要花一次模型调用来确认提示是否矛盾。

## 已落实的通用规则与验证边界

`.11` 对 Task 1 和 Task 2 都实际发出了：中性常用说法不自动判错或不礼貌；区分错误、不准确、可选替换；可选替换不列问题；声称缺少某句式之前核实是否已经出现；已有简短理由不说成完全没有展开；不为凑数制造问题。新加入的规则没有写入本批检查的五组字面措辞（`old people`、`elderly`、`carbon emissions`、`everybody`、`transported by`）。这些检查证明“提示已发出”，不能证明模型会遵守、误批已减少或评分已校准。

语言三分类仍是提示词要求，没有新增机器可核验的分类字段；不应将文本存在性测试说成已验证三分类行为。现有输出和校验不变是本轮的设计边界，本身不是新缺陷。弱文过度概括漏报这次也没有专门修复。
