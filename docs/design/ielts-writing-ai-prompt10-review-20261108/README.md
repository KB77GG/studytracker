## P2-1：把“不删”或“只删词”当成删整句/整段

位置：`tools/ielts_writing_ai/review.py:315`、`:322`、`:338`。当前只检查是否同时含有删除动词和“段/句”字样，没有确认删除动作的宾语及否定语义。

沿用真实 172 词 Task 1、引用真实的 23 词结尾句，替换建议即可复现：

| 建议 | 实际操作后的字数 | 当前程序显示 |
|---|---:|---|
| 不要删去这一段，应保留其比较信息。 | 172 | 删去整段/整句后约剩149词，低于150 |
| 删去这一句中的“In summary”两个词，保留其余内容。 | 170 | 同样错误提示149词 |
| Remove only "In summary" from this sentence, keeping the rest. | 170 | 同样错误提示149词 |

不仅建议尾部出错，评价顶部还确定地声称“有1条建议提到删去整段或整句；删去后会低于150词下限”。复制评价同样带出这些错误内容。明确的 `Do not delete...` 和引用后否定删除意见也会复现。完整输入、输出及复制行见 `deletion_probe.json` 的 `intent_scope` 场景。

这是新增程序注释的误报，不是模型原本报错，也不是学生分数或原稿被修改。应先确认是肯定的整段/整句删除动作；句内删词、否定删除、转述后拒绝的意见不能按整段扣词数。

## P2-2：忽略建议的明确目标，优先计算问题引文所在段

位置：`tools/ielts_writing_ai/review.py:317`–`:328`。候选首先放入 `issue.quote`，随后才放建议中的引文，最后无条件选择 `found[0]` 的第一个匹配单元。

这些不是泛泛要求自然语言全覆盖：动作和目标都已经明确，程序却选择了不同文本。证据见 `target_binding` 场景，已走真实 `normalize_evaluation → evaluation_text` 路径。建议将动作绑定到目标，使用明确目标时不能让问题引文覆盖它；重复或矛盾定位无法消歧时应提示无法可靠计算，避免给出确定的错误数字。
