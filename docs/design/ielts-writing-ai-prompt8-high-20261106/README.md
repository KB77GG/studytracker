### 不成功的原因是JSON结构

- 离题样本首轮：根对象提前结束，后面的 `priorities` 成为多余内容；解析报 `Extra data`。第二轮结构正确，评价成功。
- 97词短文：两次都在正文结尾解析失败（`Expecting ',' delimiter`），最终 `invalid_output`，没有产生可采用成绩。
- 仅在诊断副本补一个闭合符后，两份短文的 `argument`、`overall_comment`、`priorities` 仍错嵌在 `criteria` 中。问题不只是少一个括号，正式拒绝是正确行为。
- 三次均HTTP200、stop；对应输出4,903 / 4,399 / 6,315 token，均低于16,000上限。这一批没有证据表明失败由输出预算截断造成。

`json_failures.json` 保存位置与上下文；`raw_calls.jsonl` 保留原样正式回答。诊断副本中补闭合符只用于解释错误，不改变原始回答、正式校验或成绩。不要重新引入宽松截取JSON、自动补结构后直接出分。
