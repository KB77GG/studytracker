## 执行与安全

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python docs/reviews/vocabulary-cache-policy-20261117/policy/aggregate_policy.py --database /absolute/path/to/app.db
```

路径必须由主审核实，不从 `config.py` 猜测，不导入 `app`、ORM或重模型。脚本只使用Python标准库、不会联网、不会加载任何学生身份、题面、词条、答案、token。学生、任务、词义等整数键仅在服务器进程内用于分组，JSON不输出任何逐人/逐任务/逐词记录或标识。结果为整体计数、比例与分布（线性插值分位数）。分能力的小样本仍须结合n解释，不据此评价个人。

数据库同时使用SQLite URI `mode=ro`、`PRAGMA query_only=ON`、严格列级只读authorizer。身份表与答案列读取也会被拒绝；DDL/DML/ATTACH/PRAGMA修改/load_extension均禁止。每查询3秒、整个审计20秒、每查询50万行上限；命令入口另有25秒硬闹钟，锁等待250毫秒。超预算或schema不符只输出固定失败标志与安全诊断（固定阶段/原因分类、异常类型、查询序号、拒绝次数和耗时），不泄露SQL/文件路径/原异常消息，不输出不完整指标。不得为获取结果直接取消预算后重跑；先查看查询计划/调整窗口或离峰执行。

脚本不持有跨查询长读事务，完整fetch后立即关闭cursor；仍会产生短暂只读负载。各查询不是一个原子快照，线上并发作答可能使极少数边界值变化。不要把 `total_changes=0` 解释成其他进程也没有写；它只证明本连接没有成功写入。

## 时间、范围与分母

- 主窗口：执行时上海日期之前28个完整自然日；另输出最近7天相同指标。今天的未完整数据不纳入行为率。当前到期快照则按执行时的UTC时间判断。
- 命令入口不接受历史as-of参数；`snapshot_utc`是本次采集开始时刻，不能将今天掌握度状态解释成某个过去时刻的历史快照。合成测试在函数层传固定时间，仅用于可复现验证。
- 数据库时间按现有服务的UTC naive存储解释，加8小时获得上海自然日。不是按宿主机时区 `date.today()`。
- 学习时间使用 `DictationRecord.created_at`（题表没有独立首答时间），复习使用 `VocabularyReviewAttempt.submitted_at`；这是服务器持久化时间，不能证明学生真正看题/无提示的时间。
- 活跃学生限定为窗口中有正式词汇作答、复习结算或词汇任务完成证据的学生；不是全校/全科活跃人数。未答题仅浏览的学习日无法识别。
- “每周”是从窗口起点分成四个/一个连续七天块，保留活跃学生无任务的零周。任务量分别报告有正式答题的任务和有完成记录的任务，不把答题次数当任务数。
- 任务可能跨观察窗口或尚未完成，所以任务错误比例是**窗口内观察到的部分**，不能称为整个任务的最终错误率。完成时间优先使用group flow.completed_at；同任务有该证据时忽略旧settlement，避免跨日重复造出学习日。
- 复习容量与相邻首答时间包含独立复习item的补救首答，因为它们确实消耗时间。延迟指标混合正式学习与独立复习的后续检测，并输出`retest_source_counts`；语境生产题前可能有guide/辨析，过滤guide记录不能证明没见过提示，因此这些正确率不直接等于无提示记忆保持率。

## 六类指标

1. **任务首次错误**：组学习题通过学生+任务+首答幂等标识连接持久化记录；只用正式评分题，排除context guide和当场补救题，也排除retry/correction。旧v2任务由`vocabulary_task_review_id`关联。同任务同词义在某能力中任一正式首答错误/“忘了”即计该能力错词；全能力一词义只计一次。分母是窗口内实际作答的词义，不是教师布置但未做的所有词。输出任务分布及先算每学生任务均值后的学生分布，避免重度学生权重被隐藏。未关联首答数量另报，不能假定旧数据完备。
2. **当前到期构成**：读取掌握度表的四维`due<=now`，分别输出维度数、词义去重数、互斥构成与重叠成员数。互斥词义优先级为stage0有作答标记→stage0未测→普通巩固→最高阶段维护。**stage0且last_answered_at存在称“错误状态代理”，不标成经全部历史首答重建的真实错题。** 当前 `_apply_dimension_answer` 只有错误重置stage0，未测引导则保留last为空；但外部迁移、旧数据异常与当场补救仍需另审，不能直接据本结果批量派生新队列。
   这里是**原始排期到期**，尚未做当日整词冷却、可出题材料、补救预算等过滤，不能当成首页精确可领取数。既输出全体有到期状态学生，也单列28日活跃子集。分能力队列的新必做条数也不等于词义数。
3. **每天完成量**：正式复习首答数与已settled批次数分别计数，批次完成不等于全对。提供有词汇学习活动的学生日（含零复习）、有复习的日、活跃学生×所有窗口日三个分母；另外报告每学生均值分布。题目按实际首答自然日，批次按settled_at自然日；不使用会受任务午夜宽限影响的归属review_date。
4. **单题时间代理**：仅同学生同复习session相邻正式首答提交时间差，排除非正间隔，分别用30/60/120秒阈值报告敏感性及剔除数；不跨session连接。该差包含上一题反馈/订正、下一题阅读输入和网络等待，且遗漏每批第一题，**不是纯答题反应时，也不能直接保证每日总分钟数**。
5. **错误后跨日首测**：按学生×词义×能力×自然日合并错误起点；当天任一正式首答错误产生一个错误日，找该能力下一个有正式作答的后续日期，并取当天第一次正式结果。同日订正/后一次答对不能覆盖它。分别明确输出日差1、2、3（避免“第三天”的D0/D1歧义）、成熟可观察错误日分母、实际返回检测数、正确数、返回覆盖率和每学生正确率分布。没有回来者保留在覆盖分母，但不当错误判分。近期不足观察期者剔除并可从各分母判断右截尾。多题/多任务同日暴露另报，观测记录不能证明完全无提示。**这是现有选择/间隔规则下、实际返回者的条件正确率，有幸存者与难度选择偏差；不能凭它认定间隔1天优于2天。** 窗口之前的错误不属于本次错误起点，不能解释为全历史恢复率。
6. **活动规模**：同前述活跃口径、七天块任务分布；无全校身份表读取，也没有姓名/班级/试点名单输出。

## 参数和计划需保留的边界

这些汇总帮助估算负担、数据覆盖和可试行容量，不能单独决定最优记忆间隔。P75当前完成量可能受20词默认批次及入口引导约束，并不等于学生可承受上限。新错误队列表能让查询不再扫描无关的低频巩固池，但SQL `COUNT`仍随匹配索引范围工作；新增表本身不等于严格O(1)，必做队列若未封顶也仍会积压。
