## 间隔数据能支持什么

| 窗口与错后首次跨日检测日差 | 首测正确/首测观察数 | 条件正确率 | 观察覆盖（首测观察/成熟错误日） |
| --- | ---: | ---: | ---: |
| 28天，日差1 | 277 / 543 | 51.01% | 543 / 7,585 = 7.16% |
| 28天，日差2 | 544 / 1,596 | 34.09% | 1,596 / 7,335 = 21.76% |
| 28天，日差3 | 207 / 635 | 32.60% | 635 / 6,930 = 9.16% |
| 7天，日差1 | 16 / 38 | 42.11% | 38 / 1,566 = 2.43% |
| 7天，日差2 | 97 / 209 | 46.41% | 209 / 1,316 = 15.88% |
| 7天，日差3 | 38 / 96 | 39.58% | 96 / 911 = 10.54% |

这些是既有规则选中且返回检测者的条件比例；能力/难度、近期使用习惯、不同学生及学习/复习来源并不平衡，同学生/词义也可能重复贡献错误日。最近7天的1日与2日顺序还反转了。没有随机分配，部分组观察覆盖很低，不能把51%对34%解释为“隔1天比2天提高17个百分点”。不回来者没有被判错。

更关键的是：这里测的是**出错之后首次跨日检测**，不是“已经首次成功之后，第二次成功应隔多久”的比较试验。现有正式首答记录也不能证明没有看过guide或外部提示。因此既不能认定两次足以长期掌握，也不能用这组数直接选择成功间隔1天或2天。

## 对拟议试点参数的评价（均待用户确认）

| 拟议参数 | 评价与数据边界 |
| --- | --- |
| 两次成功至少相隔2个自然日，目标错后D1/D3 | 可作明确、可调整的试行安排，贴近用户最初方向；不是本数据证明的最优间隔。实现须明确自然日口径，不把日期差偷换成精确48小时保证。 |
| 每日必做上限20道能力题 | 可作为不提高当前常见强制题量的初始上限。单位是能力题，不是20个不同单词；同词多个能力、至少两次成功、再次出错及存量都占容量，不能保证每日清空或不再积压。P75=20很可能受旧产品一批路径约束，不是承受能力测量。 |
| 连续3个不同复测日的首次作答失败转教师讲解 | 合理的停止机械循环护栏；“3”没有由本汇总验证，应明确不计当天订正次数，暂停强制循环并保留未解决状态，不能自动标掌握。 |
| 保留第7天、第30天抽查 | 有助于发现减负后的延迟遗忘；具体抽样比例与天数仍为设计参数，不是本数据算出的保证。 |
| 可选低频巩固每日最多10题 | 合理的负担控制初值。若要求额外做满就不再是可选项；既有耗时数据不足以证明每生多10题均能承受。 |

单题间隔中位约11.4秒（排除大于60秒间隔）是服务器提交间隔代理，含反馈/网络而遗漏批次首题及长停顿；不能直接把20×11.4秒写成“每天只需3.8分钟”。

两周试点可先检查完成率、实际负担、队列增长和7天保持；**第30天抽查至少需要4–6周随访**，不能在第二周就证明长期记忆没有损失。观察时同时看不同能力和学生间差异，并保留旧规则对照或明确的基线；仅首页数字下降不等于学习效果改善。
